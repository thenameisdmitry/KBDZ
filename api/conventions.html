Conventions

Rules that hold across every endpoint: how collections are paged, filtered, and sorted; how rate limits and retries behave; how to make writes safe to repeat; and how the API versions and deprecates itself. Read this once and the endpoint pages become reference material rather than instructions.

Pagination

Every collection endpoint returns the same envelope and accepts the same two parameters. A limit above 100 is clamped to 100 rather than rejected, so always read the limit the response reports back rather than the one you sent.

Pagination parameters
ParameterTypeRequiredDescription
limitintegerOptionalResults per page. Default: 20. Maximum: 100.
offsetintegerOptionalResults to skip before the page starts. Default: 0.
List envelope
FieldTypeDescription
dataarrayThe page of results. Empty when nothing matches the filter; never null.
totalintegerTotal number of records matching the filter, across all pages.
limitintegerThe limit applied to this response, after clamping to the maximum.
offsetintegerThe offset applied to this response.
Response200 OK
{
  "data": [
    "…"
  ],
  "total": 137,
  "limit": 20,
  "offset": 0
}

Walking every page

Stop when offset reaches total. Do not stop on a short page: a filter applied after paging can legitimately return fewer rows than the limit while more pages remain.

Pagination
curl -X GET "https://api.dzenterprise.io/v1/accounts?limit=50&offset=100&sort=-created_at" \
  -H "Authorization: Bearer {access_token}"

Filtering and sorting

Each endpoint documents its own filters, such as status on Accounts or account_id on Transactions. Multiple filters combine with AND. The parameters below work on every collection.

Common query parameters
ParameterTypeRequiredDescription
sortstringOptionalField to sort by. Prefix with a hyphen for descending order, for example -created_at.
created_afterstringOptionalRFC 3339 timestamp. Returns records created strictly after this instant.
created_beforestringOptionalRFC 3339 timestamp. Returns records created strictly before this instant.

Results are sorted by -created_at unless you say otherwise, so the newest record comes first. Sorting is applied before paging.

Rate limits

Requests are limited per client, per environment: 600 requests per minute on production and 120 requests per minute on UAT. Exceeding the limit returns 429 rate_limit_exceeded. Every response carries your current budget, so you can throttle before you are throttled.

Rate limit headers
FieldTypeDescription
X-RateLimit-LimitintegerRequests permitted in the current window.
X-RateLimit-RemainingintegerRequests still available in the current window.
X-RateLimit-ResetintegerUnix timestamp at which the window resets.
Retry-AfterintegerSent with 429 only. Seconds to wait before retrying.

See Errors for the retry pattern that honours Retry-After.

Idempotency

GET, PATCH, and DELETE are idempotent by definition: repeating them leaves the resource in the same state. POST is not, and a timeout leaves you unable to tell whether the resource was created.

Send an Idempotency-Key header with every POST. Generate a UUID per logical operation, not per HTTP attempt, and reuse it on retries. The first request with a given key is processed; any later request with the same key returns the original response instead of creating a second resource. Keys are retained for 24 hours.

POST /transactions
curl -X POST "https://api.dzenterprise.io/v1/transactions" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 5f2b8c14-9d7a-4e31-b6c0-1a2f3e4d5c6b" \
  -d '{
    "account_id": "acc_007",
    "type": "wire",
    "amount": 5000.00,
    "currency": "USD"
  }'

Versioning and deprecation

The major version is part of the path: /v1. It changes only for a breaking change, and two major versions run in parallel for at least twelve months.

The following are not breaking changes, and your client must tolerate them without a release:

  • A new field added to a response object.
  • A new optional request parameter.
  • A new value added to an existing enumeration.
  • A new endpoint or a new error code.

When an endpoint is deprecated, its responses carry a Deprecation header with the date it was announced and a Sunset header with the date it stops responding. Both are announced in the changelog before the header appears.

Data formats

The API accepts and returns application/json only, and field names are lower case with underscores.

Formats used across the API
FieldTypeDescription
TimestampsstringRFC 3339 in UTC, for example 2026-03-15T10:30:00Z. Fields ending in _at are timestamps.
DatesstringISO 8601 calendar dates without a time component, for example 2026-01-15. Fields ending in _date are dates.
MoneynumberDecimal in the major unit of the currency, for example 12500000.00 for GBP. Always paired with a currency field.
CurrencystringISO 4217 three-letter code in upper case, for example GBP.
IdentifiersstringOpaque, prefixed strings such as acc_007 or prt_BNPParibas_001. Treat them as opaque and never parse them.
EnumerationsstringLower case with underscores, for example money_market. New values may be added in a minor release.

Null and absent

A null field is present and deliberately empty. An absent field was not returned at all, usually because your token lacks the scope to see it. On PATCH, sending null clears a value, whereas omitting the field leaves it untouched.
