Errors

Every failed request returns a standard HTTP status code and a JSON body with the same shape. Handle errors by switching on the error field, which is stable across releases, rather than on the message text, which is not.

The error object

All errors share one envelope. A 422 adds a details array naming each field that failed validation; every other error omits it.

Error object
FieldTypeDescription
errorstringStable, machine-readable error code. Switch on this value, never on the message.
messagestringHuman-readable explanation. Wording may change between releases, so do not parse it.
statusintegerHTTP status code, repeated in the body for clients that log bodies only.
request_idstringIdentifier for this call. Quote it in any support request.
detailsarrayPresent on 422 only. One entry per rejected field, each with field and issue.
Response422 Unprocessable Entity
{
  "error": "validation_failed",
  "message": "The request contains one or more invalid fields.",
  "status": 422,
  "request_id": "req_9f3c21a7",
  "details": [
    {
      "field": "currency",
      "issue": "Must be a valid ISO 4217 code."
    },
    {
      "field": "maturity_date",
      "issue": "Must be later than start_date."
    }
  ]
}

Error codes

The codes below apply to every endpoint. Endpoint pages list only the errors specific to that resource.

Status codes and how to resolve them
StatusError codeWhat it meansHow to fix it
400invalid_requestThe request could not be parsed: malformed JSON, an unknown query parameter, or a missing required field.Validate the request body against the schema and check that Content-Type is application/json.
401unauthorizedThe Bearer token is missing, malformed, or has expired.Request a new token from the auth server and retry. Tokens expire after 3600 seconds.
403insufficient_scopeThe token is valid but does not carry the scope this endpoint requires.Request a token with the required scope (for example api:write for POST, PATCH, and DELETE).
404not_foundNo resource exists with the supplied identifier, or it is outside your environment.Check the identifier and confirm you are calling the environment the resource belongs to.
409conflictThe request conflicts with the current state of the resource, for example deleting an Account that still holds an open Position.Fetch the resource, resolve the conflicting state, then retry.
422validation_failedThe request was well formed but a field value is not acceptable, for example an unknown currency code or a maturity date in the past.Read the details array: it names every field that failed and why.
429rate_limit_exceededYou have sent more requests than your plan allows in the current window.Back off and retry after the number of seconds given in the Retry-After header.
500internal_errorAn unexpected error occurred on our side. The request was not processed.Retry with exponential backoff. If it persists, contact support with the request_id.
503service_unavailableThe service is temporarily unavailable, usually during a scheduled maintenance window.Retry after the interval given in the Retry-After header.

Retrying safely

Retry 429 and 5xx only. The remaining 4xx errors describe a problem with the request itself and will fail again on every attempt. When a response carries a Retry-After header, wait at least that many seconds; otherwise back off exponentially.

Reporting a problem

Every response, successful or not, carries a request_id. Include it when you contact support: it resolves to the exact call in our logs and turns a diagnostic conversation into a lookup.
