Transactions

Submit, process, approve, and reject Transactions of six types: wire, money_market, security, fx_trade, cashflow, and loan_tranche.

In the DZ Enterprise environment, a Transaction is an order submitted and processed within the Transactions module. Once approved, the order is issued and sent to the named institution (bank, hedge fund, or counterparty broker) for execution. For Transaction workflows, see the Transactions Guide.

GET/transactions

List transactions

Returns a paginated list of Transactions. Filter by account, portfolio, type, or status.

Query parameters
ParameterTypeRequiredDescription
account_idstringOptionalFilter by Account ID.
portfolio_idstringOptionalFilter by Portfolio ID.
typestringOptionalTransaction type. One of: wire, money_market, security, fx_trade, cashflow, loan_tranche.
statusstringOptionalTransaction status. One of: pending, processing, completed, failed, cancelled.
limitintegerOptionalResults per page. Default: 20. Maximum: 100.
offsetintegerOptionalResults to skip before the page starts. Default: 0.
Request
curl -X GET "https://api.dzenterprise.io/v1/transactions?account_id=acc_007&type=wire&limit=20" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json"
Response fields
FieldTypeDescription
dataarrayThe page of Transaction objects. Empty when nothing matches, never null.
totalintegerTotal Transactions matching the filter, across all pages.
limitintegerThe limit applied to this response, after clamping to 100.
offsetintegerThe offset applied to this response.

Fetches the full record for a single Transaction, including metadata and status.

POST/transactions

Create transaction

Records a Transaction. It starts in pending status and is processed asynchronously.

Request body
ParameterTypeRequiredDescription
account_idstringRequiredAccount the Transaction settles against.
portfolio_idstringRequiredPortfolio the Transaction belongs to.
typestringRequiredTransaction type. One of: wire, money_market, security, fx_trade, cashflow, loan_tranche.
amountnumberRequiredPositive decimal in the major unit of currency. Direction follows type.
currencystringRequiredISO 4217 currency code for this Transaction.
referencestringOptionalReference carried through to the counterparty for reconciliation.
notesstringOptionalFree-text note attached to this Transaction.
Always send an Idempotency-Key. This endpoint moves money: without a key, a network timeout leaves you unable to tell whether the Transaction was created, and a blind retry can issue the order twice. Generate one key per payment and reuse it on every attempt.
Request
curl -X POST "https://api.dzenterprise.io/v1/transactions" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 5f2b8c14-9d7a-4e31-b6c0-1a2f3e4d5c6b" \
  -d '{
    "account_id":   "acc_007",
    "portfolio_id": "prt_BNPParibas_001",
    "type":         "wire",
    "amount":       5000000.00,
    "currency":     "USD",
    "reference":    "TN_MM_10062026_89",
    "notes":        "Initial position entry"
  }'

PATCH/transactions/{id}

Update transaction

Updates the mutable fields of a Transaction. Only a pending Transaction can have its status changed.

Path parameters
ParameterTypeRequiredDescription
idstringRequiredUnique Transaction ID.
Request body
ParameterTypeRequiredDescription
statusstringOptionalNew status. One of: completed, failed, cancelled. Valid only from pending.
referencestringOptionalUpdated reference string.
notesstringOptionalUpdated note. Send null to clear it.

Changing the status of a Transaction that has left pending returns 409 conflict. Settled money movements are part of the audit trail and cannot be rewritten.

Request
curl -X PATCH "https://api.dzenterprise.io/v1/transactions/TN_WIRE_10062026_78" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{"status": "completed", "reference": "TN_MM_10062026_89"}'

DELETE/transactions/{id}

Remove transaction

Deletes a Transaction record. Only Transactions with pending or failed status can be deleted.

Path parameters
ParameterTypeRequiredDescription
idstringRequiredUnique Transaction ID to delete.

A completed Transaction cannot be deleted and returns 409 conflict. Reverse it with a compensating Transaction instead.

Request
curl -X DELETE "https://api.dzenterprise.io/v1/transactions/TN_WIRE_10062026_78" \
  -H "Authorization: Bearer {access_token}"
Response204 No Content
// No body returned
