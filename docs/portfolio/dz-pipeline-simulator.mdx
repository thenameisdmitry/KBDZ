# Data Hub: Interactive Pipeline Simulator

**DZ Data Hub** is a fictional
data platform: Snowflake as the warehouse, dbt for transformations, Airflow for
orchestration, Metabase for consumption. This page demonstrates my ability as Technical Writer to construct mock-ups and real workflow presentation, where every layer is explained in details.

## What the simulator shows

The simulator traces five billing events through one pipeline: a raw landing
table, a dbt staging model, a conformed dimension, a fact table, and finally a governed
business metric (Trial-to-Paid Conversion Rate). Press **Run** to watch one execution running step-by-step.
Or click any node in the DAG to read its documentation.

:::note NOTE
The sample data is deliberately imperfect. The raw layer contains a duplicate event, an
inconsistently cased event type, and an internal test account: the three most common
data-quality problems in event pipelines. The documentation explains where each problem
is handled, why it is handled *there* and nowhere else, and what contract each layer
guarantees to the next.
:::

## The documentation model

Every node carries three layers of documentation, each written for a different reader:

1. **Overview**: purpose, ownership, grain, schedule, and freshness guarantees in plain language
2. **Schema**: the contract. Column-level descriptions that state what can be assumed about it (uniqueness, casing, timezone) and what cannot.
3. **Code**: the commented source itself. Comments capture
   design intent.

The premise: documentation that lives in one narrative document goes stale, while
documentation attached to the thing it describes is updated along with the development cycle. The simulator makes that structure tangible.

## Metric governance

The final node treats a business metric as a documented, versioned object. Its page carries a canonical definition, split business/technical
ownership, explicit caveats (the 30-day conversion window makes the latest month
incomplete; account attributes reflect current state under SCD1), and a change log
recording that the window was unified across dashboards in v1.2. Every convention shown
in the metric (the `acc_9xx` test-account range, the naming, the window) is consistent
with the upstream nodes, because that consistency is the whole point.

## How it is built

The simulator is a single self-contained React component: an SVG DAG with an animated
execution run, a tabbed documentation panel, a stage-by-stage data preview, and a small
hand-rolled syntax highlighter. It respects
`prefers-reduced-motion` and runs entirely in the browser. The IDE-style dark theme is
intentional: the artifact is meant to read as a working tool, not a slide.
