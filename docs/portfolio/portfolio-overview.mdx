# Portfolio

This Portfolio shows writing samples, documentation tooling, and working artifacts from my practice as a
**Senior Technical Writer** and **Team Lead**.

Most of the product documentation here comes from my most recent role at **Hazeltree**, a
fintech SaaS platform for treasury management: cash optimization, portfolio profitability
analysis, and financial risk management. The engineering and AI sections are original work
built for this portfolio.

:::tip[If you have only five minutes for my Portfolio]
Three pages give the clearest picture of how I work:

1. [Transaction Matching](./Case-5-Transaction-Matching): a guide that explains an
   algorithm to people who have to trust its output.
2. [Documentation Assistant](./docs-assistant): ask the guides above a question and see
   what an AI assistant can answer from them.
3. [How I Work](./How-I-Work): the operating process behind all of it, in one page.
:::

## Product Documentation

Customer-facing documentation written for an enterprise fintech platform: knowledge base
guides, conceptual overviews, getting-started articles, and step-by-step implementation
instructions across five product modules.

Each sample opens with a short summary giving the context it was written under: intended
audience, documentation objective, and the business and compliance constraints that shaped
it. The section also contains a [release notes sample](./releasenotes) showing how I
structure release communication so stakeholders can act on it.

:::note[Confidentiality]
Company-specific information and sensitive implementation details in the Hazeltree samples have been removed, blurred, anonymized, or generalized. The samples preserve the original structure, writing style, and technical depth.
:::

## Documentation Engineering

Documentation work that is closer to building than to writing.

- **[Automation Scripts](./code-samples)**. A production Python tool that pulls release
  information from TFS queries into a single structured file, removing hours of manual
  collection from every release cycle.
- **[Pipeline Simulator](./dz-pipeline-simulator)**. An interactive artifact documenting
  a Snowflake, dbt, Airflow and Metabase data platform, with per-node documentation,
  schema contracts, and metric governance.

## AI & RAG

Documentation now has a second reader: the retrieval system behind a support agent or an
IDE assistant. This section is about what that changes, demonstrated rather than claimed.

- **[Writing for AI Retrieval](./ai-retrieval)**. The rules that decide whether a fact
  survives chunking, and the failure each one prevents.
- **[Documentation Assistant](./docs-assistant)**. A retrieval assistant answering real
  questions from the five guides above, including a retrieval defect it found in them.
- **[Retrieval Pipeline](./retrieval-pipeline)**. One question walked through seven
  stages, labelling which failures belong to the writer and which to the platform.
- **[RAG Evaluation in CI](./rag-evaluation)**. Treating agent answers as a test suite
  that gates every documentation change.
